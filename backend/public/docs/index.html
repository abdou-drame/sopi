Introduction

API REST de Sopi (réservation de services de proximité à Keur Massar). Préfixe /api/v1, JSON uniquement, erreurs en français : { "message": "...", "errors": { "champ": ["..."] } }.

Base URL: http://localhost:8000 
This documentation aims to provide all the information you need to work with our API.

<aside>As you scroll, you'll see code examples for working with the API in different programming languages in the dark area to the right (or as part of the content on mobile).
You can switch the language used with the tabs at the top right (or from the nav menu at the top left on mobile).</aside>

Authenticating requests

To authenticate requests, include an Authorization header with the value "Bearer {VOTRE_JETON}".

All authenticated endpoints are marked with a requires authentication badge in the documentation below.

Le jeton est renvoyé par POST /api/v1/auth/connexion ou /auth/inscription.

    --header "Content-Type: application/json" \
    --header "Accept: application/json"
const url = new URL(
    "http://localhost:8000/api/v1/admin/prestataires/demandes"
);

Refuser une demande

requires authentication

Le compte passe à refuse, ses justificatifs à rejete et le motif est enregistré (visible sur le lien de suivi du prestataire). Seule une demande en_attente peut être décidée.

Example request:
curl --request POST \
    "http://localhost:8000/api/v1/admin/prestataires/0198a1b2-0000-7000-8000-000000000002/refuser" \
    --header "Authorization: Bearer {VOTRE_JETON}" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"motif\": \"La photocopie de la CNI est illisible.\"
}"

const url = new URL(
    "http://localhost:8000/api/v1/admin/prestataires/0198a1b2-0000-7000-8000-000000000002/refuser"
);

const headers = {
    "Authorization": "Bearer {VOTRE_JETON}",
    "Content-Type": "application/json",
    "Accept": "application/json",
};

let body = {
    "motif": "La photocopie de la CNI est illisible."
};

fetch(url, {
    method: "POST",
    headers,
    body: JSON.stringify(body),
}).then(response => response.json());

Administration — sanctions

Routes réservées aux administrateurs (jeton Sanctum + rôle administrateur). Poser et lever une sanction sont limités à 10 requêtes par minute. Une suspension ou un bannissement est « tout ou rien » : sanction, statut du compte et révocation de tous ses jetons dans une seule transaction. Le compte ne peut plus se connecter (le message de refus indique le motif et, pour une suspension, la date de fin), disparaît de la recherche et du profil public, et ses réservations à venir (en attente, acceptées, confirmées pour un prestataire ; en attente et acceptées pour un client) sont annulées, un prestataire sanctionné voyant l'acompte versé remboursé en intégralité. Une prestation en cours va à son terme. Le solde et les retraits ne sont pas modifiés. Un administrateur ne peut pas être sanctionné.

Revenus de la plateforme

requires authentication

Série par jour, semaine (lundi à dimanche) ou mois calendaire, sur une période de 366 jours au plus (bornes incluses, fuseau Africa/Dakar). Par défaut : les 30 derniers jours, par jour. Les périodes vides sont présentes avec des zéros. Définitions : revenus = commissions des paiements réussis dont le crédit au prestataire est fait (prestation terminée), datées par ce crédit, paiements remboursés exclus ; acomptesEncaisses = acomptes des paiements réussis, datés par le paiement ; remboursements = acomptes remboursés, datés par le remboursement ; retraitsVerses = retraits réussis, datés par leur traitement. soldePrestataires est le cumul des soldes à l'instant de la demande. Montants en FCFA entiers.

Alertes

requires authentication

Éléments qui demandent l'attention de l'administrateur, calculés à la demande (rien n'est envoyé : l'administrateur ne reçoit ni e-mail ni notification push). Liste vide quand tout est calme. Triées de la plus grave à la moins grave. Types : dossiers_en_attente, litiges_ouverts, avis_signales, retraits_bloques, remboursements_en_echec, remboursements_en_retard, notifications_en_echec, suspensions_a_echeance. Gravités : info, attention, critique (seuils configurables, sopi.admin.alertes.*). ids : au plus 20 identifiants, les plus anciens d'abord, pour ouvrir les éléments (le dossier est identifié par l'id du prestataire) ; compteur donne le total réel. ressource : où ouvrir les ids dans l'administration (demandes-prestataires : /admin/prestataires/{id}, litiges, retraits, paiements, notifications : /admin/notifications-en-echec/{id} ; avis : liste /admin/avis?aTraiter=1 ; sanctions : liste /admin/sanctions?echeanceDansHeures=24). ageMinutes : ancienneté du plus ancien élément ; echeanceDansMinutes : délai avant la première fin de suspension.

Authentifie un compte actif. Un compte non actif reçoit 403 avec message et, quand elles existent, des informations structurées : motif (sanction active, ou motif du refus d'inscription) et finSuspension (ISO 8601, suspension temporaire seulement). Le champ statutCompte (en_attente, refuse, suspendu ou banni) accompagne toujours ce 403. Les autres champs sont absents sinon.

Example request:
curl --request POST \
    "http://localhost:8000/api/v1/auth/connexion" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json" \
    --data "{
    \"identifiant\": \"awa@example.com\",
    \"password\": \"MotDePasse123\"
}"

const url = new URL(
    "http://localhost:8000/api/v1/auth/connexion"
);

const headers = {
    "Content-Type": "application/json",
    "Accept": "application/json",
};

let body = {
    "identifiant": "awa@example.com",
    "password": "MotDePasse123"
};

fetch(url, {
    method: "POST",
    headers,
    body: JSON.stringify(body),
}).then(response => response.json());

Ouvrir un litige

requires authentication

Signale un problème sur une de vos réservations confirmee, en_cours ou terminee. Envoi JSON, ou multipart pour joindre jusqu'à 3 photos de preuve (preuves[]). Une réservation ne peut engendrer qu'un seul litige, même une fois clôturé. Le prestataire peut répondre, puis un administrateur tranche. Aucun remboursement n'est déclenché automatiquement.

Example request:
curl --request POST \
    "http://localhost:8000/api/v1/reservations/0198a1b2-0000-7000-8000-000000000060/litiges" \
    --header "Authorization: Bearer {VOTRE_JETON}" \
    --header "Content-Type: multipart/form-data" \
    --header "Accept: application/json" \
    --form "motif=Prestataire absent"\
    --form "description=Le prestataire ne s'est pas présenté au rendez-vous."\
    --form "preuves[]=@test.jpg" 
const url = new URL(
    "http://localhost:8000/api/v1/reservations/0198a1b2-0000-7000-8000-000000000060/litiges"
);

const headers = {
    "Authorization": "Bearer {VOTRE_JETON}",
    "Content-Type": "multipart/form-data",
    "Accept": "application/json",
};

const body = new FormData();
body.append('motif', 'Prestataire absent');
body.append('description', 'Le prestataire ne s'est pas présenté au rendez-vous.');
body.append('preuves[]', document.querySelector('input[name="preuves[]"]').files[0]);

fetch(url, {
    method: "POST",
    headers,
    body,
}).then(response => response.json());
